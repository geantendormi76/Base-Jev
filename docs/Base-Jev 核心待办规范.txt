## 1. 核心背景与技术债务根因（Root Cause）

### 1.1 现状与矛盾
* **现象**：当前 `Invar` 进行 1,216 个端点推演时，必须切换到 `C:\dev\Base-Jev`，调用庞大且依赖 PyTorch/CUDA 的 `generate_triage_predictions.py`，无法单兵独立运行。
* **根因**：虽然 `Base-Jev` 此前导出了单文件 `system_one_unified.onnx`（1.28 GB）并交付给了 Invar，**但该 ONNX 模型的计算图中遗漏了 `sensitivity_head`（敏感度头）的物理连通**！

### 1.2 真实代码物证链
1. **`C:\dev\Base-Jev\python\packages\core\src\decision_heads.py`**：
   * 模型实际训练了两个独立的评分头：
     ```python
     self.impact_head = ScoreOrdinalHead(hidden_size, score_max_levels)      # 破坏力头
     self.sensitivity_head = ScoreOrdinalHead(hidden_size, score_max_levels) # 敏感度头
     self.score_head = self.impact_head  # 默认回退别名
     ```
   * 其统一方法 `forward_score` 写死只调用了破坏力头：
     ```python
     def forward_score(self, q_hidden, active_levels=None):
         return self.impact_head(q_hidden, active_levels)  # 遗漏了 sensitivity_head！
     ```
2. **`C:\dev\Base-Jev\python\packages\core\src\onnx_export_wrapper.py`**：
   * ONNX 导出包装器只设计了单个评分输入 `score_q_pos`，且只调用了 `forward_score`：
     ```python
     score_q_vecs = torch.index_select(seq_hidden, 0, score_q_pos)
     _, score_dist, score_expected = self.heads.forward_score(score_q_vecs)
     return choice_probs, bool_probs, score_dist, score_expected
     ```
3. **`C:\dev\Base-Jev\models\invar-intent-0.6b-v1\system_one_unified.onnx`**：
   * 实测导出的输出节点仅有 4 个：`choice_probs`, `bool_probs`, `score_dist`, `score_expected`。
   * **`sensitivity_head` 在导出阶段被 ONNX 常数折叠判定为无输出分支的死代码，未参与计算图构建！**
4. **历史临时妥协**：
   * 开发者因此在 `generate_triage_predictions.py` 中绕过了 ONNX，直接用 PyTorch 分别执行：
     ```python
     _, imp_dist, imp_exp = model.heads.forward_impact(q_imp)
     _, sens_dist, sens_exp = model.heads.forward_sensitivity(q_sens)
     ```
   * 这直接导致 Invar 无法在没有 PyTorch 的情况下通过现存 ONNX 获得真实的敏感度分数。

## 3. 详细改造实施步骤（Action Items）

### 第一步：修改 `Base-Jev` 的 ONNX 导出包装器
* **目标文件**：`C:\dev\Base-Jev\python\packages\core\src\onnx_export_wrapper.py`
* **改动点**：
  在输入中区分（或顺序解构）破坏力与敏感度的问题锚点，同时调用两个独立的打分头，并导出双输出：
  ```python
  # 修改前:
  def forward(self, input_ids, attention_mask, choice_q_pos, choice_cand_pos, choice_mask, bool_q_pos, score_q_pos):
      ...
      _, score_dist, score_expected = self.heads.forward_score(score_q_vecs)
      return choice_probs, bool_probs, score_dist, score_expected

  # 修改后方案 (推荐：明确分离两只物理头):
  def forward(
      self,
      input_ids: torch.Tensor,
      attention_mask: torch.Tensor,
      choice_q_pos: torch.Tensor,
      choice_cand_pos: torch.Tensor,
      choice_mask: torch.Tensor,
      bool_q_pos: torch.Tensor,
      impact_q_pos: torch.Tensor,       # (num_impact_queries,)
      sensitivity_q_pos: torch.Tensor,  # (num_sens_queries,)
  ):
      ...
      # 汇聚破坏力特征向量并推演
      imp_q_vecs = torch.index_select(seq_hidden, 0, impact_q_pos)
      _, imp_dist, imp_expected = self.heads.forward_impact(imp_q_vecs)
      
      # 汇聚敏感度特征向量并推演
      sens_q_vecs = torch.index_select(seq_hidden, 0, sensitivity_q_pos)
      _, sens_dist, sens_expected = self.heads.forward_sensitivity(sens_q_vecs)
      
      return choice_probs, bool_probs, imp_dist, imp_expected, sens_dist, sens_expected
  ```
